### Описание проекта

**Для чего я решил сделать проект?**

- Он демонстрирует мой опыт на предыдущем месте работы B2G-проект ERP (копия 1С для госструктур).
- Проект, над которым команда разработки трудилась в течение **9–10 месяцев** активной разработки и анализа (в расчёт не беру время на доработки от заказчиков, переписывание ТЗ, созвоны и масштабное тестирование - ушло в целом около 3 лет на проект), выполнен мной **за 3 дня**
- Проект призван заменить 1С и адаптировать её под нужды конкретного предприятия. Предполагаемое ускорение разработки такой ERP по сравнению с 1С примерно в 4–5 раз за счёт импорта конфигураций вместо ручного «вбивания» всех метаданных.
- Возможность переноса конфигурации **в 100 раз быстрее** (я не шучу): копирование огромной ERP-базы **ужас для современного бизнеса**. Вместо экспорта/импорта конфигурации весом 5+ ГБ выполняется перенос небольших конфигурационных файлов и HTML-кода макетов, которые можно хранить в GitLab вашего предприятия и оперативно обновлять и клонировать себе в рабочее пространство.

**Ключевые качества проекта:**

- **Быстрая масштабируемость через конфигурацию YAML** - нет необходимости настраивать все атрибуты и метаданные вручную, как в 1С. Импорт конфигураций выполняется при старте серверного приложения.
- **HTML-макеты** могут быть реализованы как импорт-/экспортируемая сущность для макетов документов с возможностью открытия в любом популярном браузере для предпредпросмотра перед импортом/экспортом.
- **Умный импорт** - вы загружаете только архив с файлами конфигурации и HTML-макетами, а система сама распознаёт и интегрирует их в логику. При проблемах выдаёт предупреждения.
- **Готовая конфигурация «из коробки»** - сидинг метаданных легко выполнить при развёртывании сервисов.
- Файлы конфигураций можно достаточно просто спроектировать по шаблону как вручную, так и с помощью нейросетей (для чего проект и предназначен).
- Внедрение возможности разработки ERP с современными паттернами разработки и использованием ИИ.
- Проект разработан на самых популярных технологических решениях с широкой экосистемой **FastAPI + React**, что позволяет быстро расширять команду разработчиков.
- Возможность многопоточных вычислений по сравнению с 1С.
- Возможность легко менять UI через токены в настройках `theme.ts` в React-части (фронтенде).
- Python предоставляет возможности использовать экосистему библиотек нейронных сетей и интеграции мессенджеров.
- Читаемая и визуально простая архитектура проекта для профессионального разработчика.
- Интуитивный UX-дизайн клиентской части подходит для любого пользователя: бухгалтера, кладовщика, кассира и т.д.
- Добавление справочников и проведение документов делается быстрее и понятнее, чем в 1С.

**Демонстрация навыков в проекте:**

- Глубокое понимание языков **Python** и **JavaScript/TypeScript**.
- Понимание используемых фреймворков **FastAPI, React**.
- Понимание используемых технологий **PostgreSQL, SQLAlchemy, Pydantic, Docker, Vite, Material UI, Yup, Handlebars**.
- Знание серверной архитектуры и **REST API**.
- Понимание **Docker** как инструмента для развёртывания сервисов проекта в единой сети.
- Умение работать с **PowerShell** как с платформой для тестирования и работы с файловой структурой проекта.
- Умение быстро работать и понимать **нейрослоп** для ускорения разработки и тестирования кода (без понимания технологий, паттернов и антипаттернов невозможно создать и довести до ума приложение, сгенерированное ИИ).
- Проект разработан **за несколько дней** - обратите внимание на даты на скриншотах.
- Умение работать с **Git по Git Flow** - скриншоты коммитов есть.

**Минусы проекта:**

- Шаблон для макетов нужно писать либо промптом нейросети, либо отдавать верстальщику. Макеты только импортируются в систему. Разрабатывать конструктор макетов это оверхед для моего проекта.
- Авторизации нет. Для моего проекта это пока не нужно: JWT-токенизация непростой механизм для отладки, и в ней нет смысла для демонстрации главных фич проекта (но опыт разработки авторизации в приложении у меня есть).
